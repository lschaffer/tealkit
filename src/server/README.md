# TealKit Server

Headless Dart/Linux daemon that exposes TealKit's agentic task runner over a
REST HTTP API.  Run it on a server, NAS, or Raspberry Pi and let the mobile
app control it remotely.

---

## Quick start with Docker Compose

```bash
# From the repo root
cd server
docker compose up -d
```

The server will be available at `http://localhost:7771`.

Check it:
```bash
curl http://localhost:7771/health
# {"status":"ok","timestamp":"..."}
```

### Docker Compose with Persistent Volume Mappings

Example `docker-compose.yml` service with required and optional mappings:

```yaml
services:
  tealkit_server:
    image: tealkit_server:prod-full
    container_name: tealkit_server
    restart: unless-stopped
    ports:
      - "7771:7771"
    environment:
      - TZ=UTC
      # - TEALKIT_API_KEY=change_me
    volumes:
      # REQUIRED: server DB/config/state/master key
      - /apps/containers/vol/tealkit_server/data:/data

      # RECOMMENDED: persistent working area
      - /apps/containers/vol/tealkit_server/tealkit:/tealkit

      # RECOMMENDED: persistent file storage used by TealKit
      - /apps/containers/vol/tealkit_server/files:/tealkit/files

      # OPTIONAL (read-only): external docs for indexing
      - /apps/containers/vol/tealkit_server/upload:/home/tealkit/upload:ro
```

Mapping purpose summary:

| Container path | Required | Purpose |
|---|---|---|
| `/data` | Yes | Main persistent state (DuckDB, encrypted settings, runtime/scheduler state, keys). |
| `/tealkit` | Recommended | Persistent runtime workspace. |
| `/tealkit/files` | Recommended | Files used/generated by workflows and MCP-related file operations. |
| `/home/tealkit/upload` | Optional | External read-only document source for server-side document indexing. |

Important:

- Document index paths must be absolute container paths (example: `/home/tealkit/upload` or `/home/tealkit/upload/doc`).
- If using `:ro`, TealKit can read/index files but cannot create folders/files there.
- A host subfolder must exist to be visible in container.

## Running without Docker

Requirements: Dart SDK ≥ 3.10.7, `libduckdb.so` on `LD_LIBRARY_PATH`.

```bash
cd server
dart pub get
dart run bin/tealkit_server.dart
```

Or compile to a native executable:
```bash
dart compile exe bin/tealkit_server.dart -o build/tealkit_server
LD_LIBRARY_PATH=../third_party/dart_duckdb/linux/Libraries/release ./build/tealkit_server
```

## Safer Internet Exposure (HTTPS Reverse Proxy)

If you want TealKit reachable from outside your LAN, prefer an HTTPS reverse proxy (nginx) instead of exposing raw port `7771` directly.

Recommended setup:

1. TealKit listens privately on `127.0.0.1:7771` (or Docker internal network).
2. nginx terminates TLS (`443`) and forwards `/tealkitserver/` to TealKit.
3. Firewall only exposes `443` (and `80` for certificate issuance/renewal).

Minimal nginx example:

```nginx
server {
  listen 80;
  server_name your.domain.tld;
  return 301 https://$host$request_uri;
}

server {
  listen 443 ssl http2;
  server_name your.domain.tld;

  ssl_certificate /etc/letsencrypt/live/your.domain.tld/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/your.domain.tld/privkey.pem;

  add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
  client_max_body_size 25m;

  location /tealkitserver/ {
    proxy_pass http://127.0.0.1:7771/tealkitserver/;
    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_connect_timeout 30s;
    proxy_send_timeout 120s;
    proxy_read_timeout 120s;
  }
}
```

In the mobile/desktop app, use:

```text
https://your.domain.tld/tealkitserver
```

Extra hardening options:

- Restrict source IP ranges in nginx.
- Add rate limiting and fail2ban.
- Use a strong `TEALKIT_API_KEY` and rotate it if leaked.
- Keep TLS cert auto-renew enabled (certbot timer/cron).

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `TEALKIT_DATA_DIR` | `~/.tealkit-server` | Root data directory (DB, outputs, logs) |
| `TEALKIT_PORT` | `7771` | HTTP port to listen on |
| `TEALKIT_HOST` | `localhost` | Host/IP to bind (`0.0.0.0` for Docker) |
| `TEALKIT_API_KEY` | *(unset)* | Optional Bearer token guard. Supports a single key (`key1`) or multiple keys (`key1,key2` or `["key1","key2"]`). All non-`/health` routes require `Authorization: Bearer <one_of_keys>` |

## API Summary

### Health
| Method | Path | Description |
|---|---|---|
| GET | `/health` | Returns `{"status":"ok"}` |
| GET | `/status` | Returns server status, LLM config, scheduler state |

### Tasks
| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/tasks` | List all tasks |
| GET | `/api/v1/tasks/<id>` | Get a single task |
| POST | `/api/v1/tasks` | Create task (requires `title`, `llm_prompt`) |
| PUT | `/api/v1/tasks/<id>` | Partial update |
| DELETE | `/api/v1/tasks/<id>` | Delete |
| POST | `/api/v1/tasks/<id>/run` | Trigger immediate one-off run → `202` |
| POST | `/api/v1/tasks/<id>/cancel` | Cancel in-progress run |
| GET | `/api/v1/tasks/<id>/output` | Retrieve last run output |

### Settings
| Method | Path | Description |
|---|---|---|
| GET/PUT | `/api/v1/settings/llm` | LLM provider & model |
| GET/PUT | `/api/v1/settings/data-sources` | Email, web search, SSH, Slack, etc. |
| GET/PUT | `/api/v1/settings/preferences` | Output path, retention, locale |
| GET/PUT | `/api/v1/settings/external-tools` | External MCP tool servers |

### Scheduler Log
| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/scheduler/log?limit=50&offset=0` | Paginated run history |

### MCP Proxy
| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/mcp/servers` | List configured MCP servers with status |
| POST | `/api/v1/mcp/servers/<id>/start` | Connect/start a server |
| POST | `/api/v1/mcp/servers/<id>/stop` | Disconnect/stop a server |
| GET | `/api/v1/mcp/servers/<id>/tools` | List available tools |
| POST | `/api/v1/mcp/servers/<id>/tools/<name>/call` | Call a tool |
| GET | `/api/v1/mcp/servers/<id>/events` | SSE stream (stdio servers only) |

### Sync
| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/sync/tasks` | Bulk-upsert tasks from mobile app |
| POST | `/api/v1/sync/settings` | Bulk-push all settings from mobile app |

```
$TEALKIT_DATA_DIR/
  db/           — DuckDB database file
  output/
    <task-id>/  — One .txt file per run (named by timestamp ms)
  logs/         — Server log files (future)
```
