📖 Introduction

TealKit – Mobile KI Agent is a personal AI assistant that runs directly on your phone or desktop. It connects to large language models (LLMs) — local or cloud-based — and uses a rich set of tools (data sources, MCP servers, scripts, and skills) to answer questions, execute tasks, and automate workflows.

Key Concepts

  • Local mode — the app runs entirely on your device; the LLM may be a local Ollama server or a remote API called directly from the device.
  • Server mode — the app delegates heavy processing to a companion server (useful for weaker devices or shared workloads).
  • Playground — a free-form chat interface for ad-hoc queries and prompt testing.
  • Agents — persistent, named task configurations with their own system prompts, tools, and LLM overrides.
  • Data Sources — external connections (web search, email, cloud drives, databases, etc.) that the AI can query.
  • Tool Skills — reusable code capabilities that agents can invoke.
Tip: Start with the LLM Settings to connect your preferred AI provider before using the Playground or creating agents.

When you open TealKit, you land on the home screen. From here you choose the operating mode and navigate to the main areas of the app.

Mode Switch

The segmented control at the top switches between Local and Server mode. In Local mode the app uses LLM providers configured in Settings directly. In Server mode requests are forwarded to your companion backend.

⚙️ Global Settings

Tap Settings from the home screen to open the global configuration area. Settings are grouped into tabs or sub-pages covering LLM providers, data sources, MCP servers, scripts, tool skills, general preferences, and the secure vault.

🧠 LLM Settings

TealKit supports two independent LLM slots: LLM 1 (Primary) is used for all general chat and agent tasks; LLM 2 (Coding) is automatically selected for code-related tasks when configured.

Provider & Model

Select a Provider from the dropdown (e.g. Mistral AI, OpenAI, Ollama local, Anthropic, Google Gemini, custom OpenAI-compatible). Then enter the Model name (e.g. mistral-medium-latest, mistral:14b). For cloud providers a token price summary is displayed below the model field.

Provide your API Key and optionally override the Base URL (useful for self-hosted or proxy endpoints such as a Pinggy tunnel to a local Ollama instance).

AI Data Sharing Consent

When using remote providers, you must acknowledge the AI Data Sharing Consent toggle. This confirms that your prompts and tool outputs may be sent to the selected cloud provider. You can disable this at any time to block remote calls.

SLM Mode

Enable SLM (Small Language Model) mode if you are using a lightweight local model. This reduces prompt overhead and disables features that small models cannot reliably use.

Advanced Settings

Toggle Advanced Settings to reveal fine-grained generation parameters:

ParameterDescription
TemperatureControls response randomness. Lower values (e.g. 0.2) produce focused, deterministic output; higher values (e.g. 0.8) produce more creative responses.
Max TokensMaximum tokens the model may generate per response. Set to 0 for provider default / unlimited.
Max Tool Output Size (chars)Caps the character count of any single tool result injected into the context. Prevents oversized tool outputs from consuming the context window. Example: 1 512 000 chars ≈ 1.4 MB.
Token Warning ThresholdWhen the accumulated context token count exceeds this value the app suggests a context cleanup. Example: 1 500 000 tokens.
Top KRestrict sampling to the top K most likely tokens. Leave empty for provider default.
Top PNucleus sampling threshold. Tokens are sampled from the smallest set whose cumulative probability exceeds P.
Repeat PenaltyDiscourages the model from repeating the same tokens. Values above 1.0 penalise repetition.
SeedFixed random seed for reproducible output. Leave empty for non-deterministic generation.

Thinking / Reasoning

The Thinking / Reasoning toggle enables models that support internal chain-of-thought blocks (e.g. <think> sections, QwQ, DeepSeek-R1). When enabled, the model may emit reasoning tokens before its final answer. Disable this toggle to suppress thinking output and reduce token usage on models where reasoning is optional.

Tip: The Thinking toggle is available in all three LLM configurators: global LLM Settings, the Playground LLM override, and the per-agent LLM override.

Status & Test Connection

A coloured status indicator at the bottom of the dialog shows the currently configured provider and model. Use Test Connection to verify connectivity before saving. Press Save (or the floppy-disk icon) to persist the configuration to secure on-device storage.

🌐 Remote MCP Servers

TealKit can connect to external Model Context Protocol (MCP) servers to extend the AI's tool set without embedding the tools in the app itself. MCP servers expose tools, resources, and prompts over a standardised JSON-RPC interface.

In the Remote MCP Servers settings you can add, edit, and remove server connections. Each server entry requires:

  • Name — a display label for the server.
  • URL — the endpoint address (HTTP/HTTPS or WebSocket).
  • Authentication — optional Bearer token or API key.
  • Enabled toggle — quickly enable or disable individual servers.

Once connected, tools provided by the MCP server appear alongside built-in tools in the Playground and agent tool selectors.

Tip: The built-in MCP registry (from assets/github_mcp_registry.json) lists publicly available community MCP servers that you can add with one tap.

📜 Scripts

Scripts are JavaScript snippets that the AI can execute on your device. They run inside a sandboxed JS engine (Flutter JS) and can access a set of provided APIs.

In the Scripts settings you can:

  • Create and edit named scripts using the built-in code editor.
  • Assign each script a description so the AI knows when to invoke it.
  • Enable or disable individual scripts per agent or globally.
Note: Scripts run client-side in a sandboxed environment. They cannot access the network or device file system beyond the paths explicitly granted.

🦸 Tool Skills

Tool Skills are higher-level reusable capabilities that combine multiple tools or scripts into a single named action. Unlike raw scripts, skills have structured inputs and outputs and can be composed into agent workflows.

The Tool Skills settings let you:

  • Browse and enable community skills from the built-in registry.
  • Write custom skills in the skill editor.
  • Assign skills to specific agents or make them globally available.
  • View the input schema and expected output format for each skill.

⚙️ General

The General settings cover app-wide behaviour and preferences:

  • Language — switch the app UI language (currently English and German).
  • Theme — dark mode is the default; light mode may be available in future versions.
  • Notifications — configure alerts for long-running agent tasks.
  • Background execution — allow or restrict agents from running when the app is in the background (Android / Windows).
  • Logging — toggle verbose logging for troubleshooting.
  • Context cleanup — set auto-cleanup policies for long conversations.

🔒 Vault

The Vault is a secure, encrypted key-value store for sensitive information such as API keys, passwords, and personal tokens. Values stored in the vault are:

  • Encrypted at rest using the platform's secure storage (Android Keystore / iOS Secure Enclave / Windows Credential Manager).
  • Accessible to agents and tools at runtime without exposing them in plain text.
  • Referenced by name in agent prompts using the {{vault:key_name}} syntax.

In the Vault settings you can add, rename, and delete vault entries. Values can be revealed temporarily with the eye icon for verification.

Best practice: Store all third-party API keys (SerpApi, SendGrid, SSH passwords, etc.) in the vault rather than entering them directly in data-source configuration fields.

🧪 Playground

The Playground is a free-form chat interface for interacting directly with the AI. Use it to test prompts, experiment with settings, and perform one-off tasks without creating a permanent agent.

Chat Interface

Type your message in the input field at the bottom and send it. The AI's response streams in real time. Messages are rendered with Markdown formatting — headers, lists, code blocks, and tables are all supported.

LLM Override

By default the Playground uses the global LLM 1 (Primary) settings. Tap the model selector to override the LLM for the current session:

  • Toggle Override LLM to unlock the per-session provider and model fields.
  • Optionally expand Advanced Settings to adjust Temperature, Max Tokens, Top K/P, Repeat Penalty, Seed, Max Tool Output Size, and Token Warning Threshold for this session.
  • Enable Thinking / Reasoning if the model supports internal chain-of-thought output.
Tip: The Playground LLM override is session-only — it does not change the global LLM settings. Switch back to defaults by disabling the override toggle.

Tool Selection

Before or during a conversation you can select which tools the AI may use — web search, document retrieval, scripts, MCP tools, etc. Only enabled tools are offered to the model.

System Prompt

Set a custom system prompt for the current session to steer the AI's persona, output format, or focus area. The system prompt is prepended to every message in the conversation.

Conversation Management

  • Clear / New chat — start a fresh conversation without changing settings.
  • Export — save the conversation as plain text or JSON.
  • Token counter — a token usage indicator warns you when the context window is filling up.

✅ Agents

Agents are named, persistent AI task configurations. Each agent has its own system prompt, tool set, LLM override, and scheduling options. Think of them as specialised AI assistants for specific workflows.

Agent List

The Agents screen lists all your configured agents. Tap an agent to run it, or use the edit icon to open the agent editor. A colour-coded status dot indicates whether the agent ran successfully, encountered an error, or is currently running.

Creating an Agent

1

Tap the + button on the Agents screen to create a new agent.

2

Enter a Name and optional Description.

3

Write a System Prompt that defines the agent's role and behaviour.

4

Select which Tools the agent may use from the tool picker.

5

Optionally configure a Sub-prompt editor for multi-step pipelines.

6

Optionally override the LLM (provider, model, advanced parameters including Thinking / Reasoning) for this agent.

7

Save the agent. It now appears in the agent list and can be run manually or on a schedule.

Agent LLM Override

Each agent can override the global LLM settings. In the agent editor, open the LLM tab and enable the override toggle. The same advanced parameters available in global LLM Settings are available here, including the Thinking / Reasoning toggle.

Scheduling PRO

Agents can be scheduled to run automatically at fixed intervals or at specific times of day. Use the Schedule tab in the agent editor to set up triggers. Scheduled agents run in the background using the platform's job scheduler (WorkManager on Android).

Sub-Prompts

Complex agents can be broken down into a chain of sub-prompts — ordered steps where the output of one step becomes available to the next. The sub-prompt editor lets you define each step's prompt, its input variables, and its output variable name.

🪟 Desktop Features (Windows)

TealKit is also available as a native Windows desktop application with features tailored for larger screens and desktop workflows.

Window Management

The desktop version uses a side-panel navigation layout. The agent list and playground are accessible from the left sidebar without navigating away from the current view.

Local Server Mode

On Windows, TealKit can host a local companion server so that mobile devices on the same network can offload processing to the desktop machine. Configure the server bind address and port in Settings → Server Mode.

File System Access

Desktop builds have broader file system access than mobile. The Document Index data source can index entire directory trees, and SSH/SFTP and script tools can read and write local files within configured paths.

Clipboard & Notifications

On Windows, agents can read from and write to the system clipboard. Background agent results surface as Windows toast notifications.

⚡ Advanced Techniques

Chaining Agents

Use sub-prompts to create multi-step pipelines. For example: step 1 fetches data via web search, step 2 summarises the results, step 3 formats them as a structured report.

Vault Templating

Reference vault secrets directly in system prompts and tool parameters using {{vault:key_name}}. The runtime replaces these placeholders before sending the prompt to the LLM, keeping secrets out of conversation history.

Custom MCP Tools

Deploy your own MCP server (Node.js, Python, or any language) and register it in Settings → Remote MCP Servers. This lets you expose any custom API or local service as a tool the AI can call. See JS Bridge & MCP Tool Spec for details.

Context Window Management

Long conversations consume context tokens. Use the Token Warning Threshold in LLM Settings to get a prompt when cleanup is due. You can also configure per-agent auto-cleanup policies to summarise or truncate old messages automatically.

Thinking / Reasoning Models

Models like DeepSeek-R1, QwQ, or Ollama-hosted reasoning variants emit <think>...</think> blocks before their final answer. Enable the Thinking / Reasoning toggle in LLM Settings (or per-agent / per-playground-session) to allow these blocks. Disable it to strip thinking tokens and reduce latency and token cost.

Offline Document Search

Index your documents once in Settings → Data Sources → Document Index. The embedded DuckDB database stores the index locally. Subsequent queries hit the local index without any network round-trip, making document retrieval fast and private.

Website Auto-Index

Add a list of web URLs in Settings → Data Sources → Website Auto-Index. The crawler fetches and indexes the content so agents can search it like a local knowledge base. Trigger re-indexing manually or on a schedule to keep the index fresh.

❓ FAQ

Which LLM providers are supported?

TealKit supports any OpenAI-compatible API endpoint, plus native integrations for Mistral AI, Anthropic Claude, Google Gemini, and local Ollama servers. Additional providers may be added via a custom Base URL pointing to an OpenAI-compatible proxy.

Can I use TealKit without an internet connection?

Yes. Run a local Ollama server on the same device or on your LAN and point LLM 1 to it. Disable all cloud data sources. The app, models, and document index will all operate offline.

Is my data sent to any third party?

Only if you configure a cloud LLM provider (e.g. Mistral AI, OpenAI, Anthropic) and enable the AI Data Sharing Consent toggle. Prompts and tool outputs are sent to the provider you configure. Credentials are stored encrypted on-device and are never sent to any TealKit server.

What is the difference between LLM 1 and LLM 2?

LLM 1 (Primary) handles all general queries and agent tasks. LLM 2 (Coding) is automatically substituted for tasks tagged as coding or for tools that explicitly request the coding model. You can leave LLM 2 unconfigured to always use LLM 1.

Why is the Thinking / Reasoning toggle not doing anything?

The toggle only has an effect with models that support it (e.g. DeepSeek-R1, QwQ, Ollama models with thinking capability). If your model does not emit thinking tokens the toggle is silently ignored.

How do I reset to factory settings?

Go to Settings → General → Reset App Data. This clears all configurations, vault entries, conversation history, and the document index. This action is irreversible.

Agents run but produce no output — what should I check?

  • Verify LLM connectivity with the Test Connection button in LLM Settings.
  • Check that the system prompt is not inadvertently blocking output.
  • Review agent logs via Settings → General → Logging.
  • Ensure the required data sources are enabled and credentials are valid.
